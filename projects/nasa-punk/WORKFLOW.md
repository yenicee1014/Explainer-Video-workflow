# NASA 朋克：制作过程解析

本文件区分三件事：参考作品创作者的自述、本地实际完成的代码重建、仍未完成的复刻与验收。可核对的执行记录在 [源码快照](source/README.md)、[时间轴](source/rebuild-timeline.json) 和 [核验目录](verification/README.md)。

## 1. 原片的制作方式，怎样理解

根据用户提供的原片简介，创作者负责方向与试听把关，设计侧 AI 负责调研、台本、分镜、动画代码和包装，工程侧 AI 负责渲染、对齐、混音、案例整理及网页配音操作，双方用任务文档与验收汇报协作。**这是原作者自述，不是本项目的执行日志；简介中的模型名称与具体操作没有在本项目中独立核验。**

它值得借鉴的不是把所有任务一次交给模型，而是把工作拆成可检查的中间结果：

| 分工 | 交接物 | 验收问题 |
| --- | --- | --- |
| 内容与设计 | 事实清单、台词、分镜、视觉规则 | 讲的事实是什么？哪个对象变化后能说明它？ |
| 工程 | 可寻址时间轴、可重播动画、音轨与渲染文件 | 从任意时刻跳转是否一致？资源是否齐全？ |
| 制作把关 | 样段、修订意见、核验结果 | 台词说到关键词时，画面是否真的解释了它？ |

本地重建采用同样的文档交接思路，但声音改为 macOS Tingting，视觉代码自行编写，未使用原作者工程，也未实际复现其 MiniMax 操作流程。

## 2. 先拆叙事，而不只是抄颜色

全片的解释链是：**历史字标 → 规范系统 → 功能为何可信 → 退役与回归 → 游戏变体 → 一张截图的七层拆解 → 可复用的风格词汇**。

观察每个镜头时，拆成五项：台词锚点、画面对象、发生的变化、希望观众理解的事实、结束后的阅读停留。本地以联系表和字幕区域 OCR 辅助定位参考镜头，再把对象和动作写入 [STORYBOARD.md](source/STORYBOARD.md)。OCR 只是定位辅助，不是字幕校对或事实核验通过证明。

例如，“两个 A 拿掉横杠”需要让横杠先存在、再移除，让字标保持原位；“旋转能看出姿态”需要同一箭体端面真的旋转，且固定观察方向；“标签各有任务”需要把引线落在真实编号与拉片上。只推近整张截图或更换字幕，不能完成这些讲解。

## 3. 素材准备与来源记录

[prepare-rebuild-assets.py](source/scripts/prepare-rebuild-assets.py) 使用 OpenCV 做矩形裁切与四点透视校正，使用 PyMuPDF 提取 NASA 手册页，使用 Pillow 准备纹理；输出素材清单记在 [provenance.json](source/assets/rebuild/provenance.json)。

- 手册实际采用 NASA **1976 年 1 月官方版**，展示 1975 年启用的系统，不把下载文件说成 1975 年原始版本。
- 游戏、电影、服装等部分示例从参考视频静帧分离，不是本次逐一从官方站点重新取得的素材；个别 ARC Raiders 静帧保留参考作品已有标注。
- NASA 字标使用既有向量，讲解动画围绕它叠加示意元素，不凭手绘猜比例。
- `frame_sample` 是参考抽帧的序号，不是秒数；只有 `time` 字段才直接表示秒。没有把无法核对的序号伪装成精确时间戳。
- 原视频、图片素材包、字体与第三方库二进制不随源码快照公开，文件来源及缺项见 [权利说明](SOURCES_AND_RIGHTS.md)。

## 4. 实际录音决定统一时间轴

本版文稿在 [rebuild-script.json](source/rebuild-script.json)，共 67 句、14 场。执行 [prepare-rebuild-audio.mjs](source/scripts/prepare-rebuild-audio.mjs) 时：

1. 使用 `say -v Tingting -r 240` 逐句生成录音，按文本与语速缓存。
2. 用 FFmpeg `silencedetect=noise=-45dB:d=0.08` 检测开头与结尾静音，裁切时保留小段余量与淡入淡出。
3. 用 `ffprobe` 实测裁切后的时长，保存 `duration` 与开口偏移 `onset`。
4. 每章从 0.65 秒开始放旁白，句间保留 0.38 秒；章节长度取实际录音与作者设定最短长度中较长者，再对齐到 30fps 帧格。
5. 输出 [rebuild-timeline.json](source/rebuild-timeline.json)，供场景、字幕与混音共同读取。

关键字段单位均为**秒**：

```text
chapter.start     = 章节全局起点
line.localStart   = 本句在章节内的起点
line.start        = chapter.start + line.localStart
line.anchor       = line.start + line.onset
sceneAnchor       = line.localStart + line.onset
```

这保证句级锚点有实际录音依据，但**不是词级强制对齐**。一句内部的横杠移除、引线展开等动作使用明确的作者相对偏移，尚须在正常速度听看时逐项校准，不能宣称关键词已全部精确对齐。字幕由同一份录音时间轴生成，不按字数平均分配。

## 5. 场景怎样由代码搭出来

[rebuild-scenes.mjs](source/scripts/rebuild-scenes.mjs) 返回每场 SVG 对象、GSAP 动作和动作说明；[build-full.mjs](source/scripts/build-full.mjs) 将它们写成 14 个独立 HTML 场景，再生成主时间线。

```text
rebuild-script.json → 逐句录音与静音检测 → rebuild-timeline.json
                                              ├─ makeScenes() → compositions/*.html
                                              ├─ 句级字幕 → SRT / 主片字幕轨
                                              └─ 音床 + 旁白 → rebuild-mix.m4a
素材与字体 ─────────────────────────────────────→ index.html
index.html → HyperFrames 检查与逐帧导出 → MP4 → 媒体核验
```

主画布为 1280×720 / 30fps。每场注册暂停的 GSAP timeline；主片通过 `data-composition-src`、`data-start`、`data-duration` 和轨道号挂载场景、字幕与音频。画面不是录屏后再剪接，而是按可寻址时间轴求出各帧状态后导出。

### 四个值得复用的讲解动作

| 台词锚点 | 对象与动作 | 要解释的关系 | 阅读停留 |
| --- | --- | --- | --- |
| `wordmark.crossbar` / `thrust` | 固定字标，显示并移走横杠，再指向 A 顶部 | 形状变化如何产生“向上”的读法 | 保留完整字标和箭头 |
| `manual.grid` | 手册原页上展开三格与笔宽测量 | 规范以几何关系约束复制 | 测量线绘完后保留 |
| `roll.rotate` | 箭体端面旋转 270°，固定观察箭头 | 黑白相位可帮助观察转动 | 转完后保持比较 |
| `layers.seams` 到 `wear` | 同一截图上依次定位接缝、斜纹、编号、徽章、红色拉片与裂纹 | 七层不是七张无关图片，而是同一设备的不同信息 | 每层读完再进入下一层 |

这些动作说明在 `compositions/*.beats.json`；只有少量顺序与在画面内的要求进入 `index.motion.json` 自动断言。**beats 文档写了动作，不等于该动作的语义已经被机器验收。**

## 6. 同一套视觉规则

白色 / 浅灰设备、细面板线与小号编号构成主体，四色复古彩条提供身份；强调色用于关键对象。Archivo 承担拉宽标题，Space Mono 用于编号，思源黑体支持中文。本版没有采用原片简介中列出的全部字体。

《星空》截图拆解沿用同一底图，再用跟随对象的引线和裁切镜头集中注意。手册页面、历史日期、功能图案与游戏截图分别承担证据、时间锚点、机制示意与风格案例，不相互冒充。

“ARC Raiders 可以看成 NASA 朋克的分支”在本版中仍是风格解读，不是开发者宣布的类别；七层拆法是教学工具，不是 NASA 官方手册条款。

## 7. 配乐与混音

[mix-rebuild.py](source/scripts/mix-rebuild.py) 使用 NumPy 生成低频音床、高频短音和章节噪声声标。章节声标落在画面换场附近，不用音乐节拍改动台词时间。

旁白放入 48kHz 数组；发声前后留保护区，音乐在该区间减弱一半。音床的主要频段避开语音核心区，但高频提示音仍存在，是否舒服需要人工听音。输出双声道，经 FFmpeg `loudnorm` 处理后编码 AAC。

脚本目标为 -16 LUFS；本地记录的实测约 -16.0 LUFS、真峰值 -2.5dBFS。归档不包含独立语音与音乐缓存，也不宣称音色或听感已通过全片人工验收。

## 8. 样段、全片和检查并不是一回事

先导出 31 秒字标样段，检查横杠移除与“向上推力”的连续动作，再扩展全片。完成后运行 HyperFrames 自动检查并导出 MP4，完整解码验证无损坏，查看首、中、尾及讲解关键帧。

原混音与输出音轨在 1、180、330 秒各取 15 秒做 FFT 互相关。三段固定偏移约 10.7ms，小于一帧，相关系数均超过 0.992。它只证明输出音轨没有明显漂移，**不能证明配音发音、字幕文字和画面含义都正确**。

自动报告还包含 38 条 `craft` 启发式警告，包括较长静止等提示，未因整体 `ok: true` 而删除。布局记录的头盔特写超出画布属于有意裁切，但仍保留记录。完整范围见 [verification/README.md](verification/README.md)。

未完成：全片正常速度人工听看、逐字校对、逐关键词动作校准、外部素材及系统语音权利逐项确认。上述工作未完成前，本项目只称“全片已导出的代码重建版”，不称“全复刻验收完成”。

## 9. 怎样复用到下一支视频

1. 先写事实与来源，再逐句拆对象、动作、关系和结论，先挑一个有解释动作的短段落。
2. 取得可用素材与合适的声音许可后，再录音并测时，统一时间单位与段落偏移。
3. 让字幕、标注和混音读取同一时间轴，句内没有词级锚点时显式标为待校准。
4. 将可重复的版式与对象状态写入场景生成器，不靠更换图片和颗粒闪动充当讲解。
5. 先检查短样段的连续帧与正常速度听感，再扩展全片。
6. 发布时分开记录“文件可播放”“自动检查通过”“人工语义验收”和“权利确认”，不要合并成一个完成勾选。

本仓库保存 MP4、SRT / VTT、实际成片联系表、14 场 HTML 与动作说明、实测时间轴、核心生成 / 混音脚本及脱敏核验报告。不包含参考视频、第三方图片包、字体与 GSAP 二进制、逐句录音、渲染缓存或本机路径。

源码为**非自包含快照**，补齐依赖与合法素材后才能重渲染；缺少素材时应停止构建，不用空白或示意图偷偷替代。具体文件缺项和原构建命令见 [source/README.md](source/README.md)。
